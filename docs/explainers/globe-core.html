From the test effort

Learnings that change how you look at the globe

The 100+ pure tests did not “prove the globe looks good.” They proved that most of this app’s risk is data contracts and pure transforms — while the thing your eyes watch is a separate, largely untested composition. That gap is why the UI can feel mysterious while parsers and day-frames are now locked.

1. Dual paths hide intent

Some globe content is hard-wired on EarthScene (showQuakes, plates, weather groups). Some is registry LayerController (hotspots, cyclones, terrain, home). Same screen, two ownership models — hard to form a mental model while watching.

2. “Empty” often means filter, not failure

Cyclones need ≥2 track points; quakes hide below mag floor; past-7d windows drop older events. Tests found this; the UI still under-explains it while the Earth keeps spinning like nothing is wrong.

3. The conductor is the fog

main.updateUI() still fans out to charts, chips, lists, and many scene setters. Tests peeled pure pieces out; the globe’s “why” still lives in scene-graph choices (what parents what, what spins, what is additive).

4. Visual truth ≠ epistemic badges

Phase F labels data trust. It does not label rendering pedagogy: pole ×6000, quake depth ×28, opaque shell hiding far-side markers. Watching the rotate-loop asks “is this real?” — the answer is often “exaggerated for legibility.”

So this page peels only the body: sphere + light + atmosphere + spin. Layers come in Part 2 once this core is solid in your head.

Pipeline

Render stack (no data layers)

Three.js WebGL, ACES tone mapping, dark clear color. The globe is not a photoreal Earth renderer — it is an instrument surface optimized for markers and terminator readability.

1. Renderer

  • WebGLRenderer on #geo-canvas
  • ACES Filmic · exposure 1.05
  • sRGB output · clear #060a12
  • log depth buffer (close zoom)

2. Camera + orbit

  • Perspective 45°, start ~2.8 units out
  • OrbitControls, pan off
  • min ~1.0012× radius (skin-hug)
  • near/far retighten with altitude

3. Core meshes

  • Earth sphere R=1, 96×96 segs
  • Day/night terminator shader
  • Atmosphere shell R≈1.055, BackSide
  • Optional faint wire grid
Hierarchy

Scene graph — what parents what

This hierarchy is the most important mental model. What is under surfaceGroup rotates with the planet. What is under earthGroup but outside surfaceGroup stays inertial (atmosphere limb tracks the sun, not the texture spin). 

scene
├── ambientLight // low when day-sync; higher when free/decorative
├── sunLight Directional · position = sunDir × 9
├── fillLight // opposite, weak; scales with lunar illum
├── stars // fixed points in scene space
└── earthGroup
    ├── surfaceGroup SPINS · rotation.y
    │   ├── earth mesh textures.js shader
    │   ├── grid wireframe // often hidden unless opacity slider low
    │   └── …layer groups live here when enabled…
    ├── atmosphere DOES NOT SPIN · BackSide additive
    ├── axisGroup // tilted by EOP pole (tiny → exaggerated)
    │   └── rotation axis line
    └── bodiesGroup // moon + sun markers (optional)

Why atmosphere does not spin

If the glow shell spun with the day texture, the limb bright edge would crawl with the map. Keeping it on earthGroup means the atmospheric rim always follows the sun direction in world space — the terminator moves across the map, the shell’s day/night rim stays coherent.

Why radius = 1

Unit sphere. All “heights” (markers at 1.01, atmosphere 1.055, moon at 2.8) are pure fractions of Earth radius. Real km only appear in data labels (quake depth, moon distance), not in mesh scale.

Transparency myth

“Earth opacity” is not real transparency

The footer slider is labeled like alpha. It does not set material.opacity. The surface stays opaque (transparent: false, depthWrite: true) on purpose — so far-side markers and internal quake hypocenters don’t show through the planet.

What the slider actually does

  • uSurfaceLift — day colors are forced brighter/darker (0.46–0.72 range). Lower “opacity” = darker, flatter surface, more “x-ray mood” without true see-through.
  • Wire grid — becomes visible below ~0.88 and gets slightly stronger as lift drops.
  • Atmosphere intensity — scales with the same control so the limb doesn’t look over-bright on a dim earth.
  • Clamped to 0.65–1.0 — values below 0.65 are rejected (historical “almost transparent globe” bug).

Why not real alpha?

True transparent Earth breaks depth for hypocenters and makes the far side bleed through. The product thesis for solid-earth is “the surface is a shell you inspect,” not a glass ball. Opacity language is UX debt from an earlier experiment.

Related dimming: home focus

uContextDim multiplies the whole global texture when regional home imagery / terrain is active — so the local patch reads as the focus, not a sticker on a competing full-res Earth.

Motion

Two spin philosophies (diurnal mode)

sync default instrument

During playback, dayAccumulator 0→1 maps to surfaceGroup.rotation.y = phase × 2π. One simulated day = one full spin. Moon/sun markers lerp between today and tomorrow ephemeris; lighting updates with them.

When not playing, phase is 0 — surface is parked for the scrub date’s sun/moon geometry (no decorative crawl).

free decorative

Bodies fixed to the scrub date’s geometry. Surface continuously auto-rotates each frame (autoRotate × lodFactor). Looks like a classic “spinning globe” demo.

LOD (length-of-day anomaly) slightly speeds/slows free spin — a tiny physics wink, easy to miss.

rotationLocked (Home / terrain) freezes surfaceGroup.rotation.y so orbital camera motion doesn’t fight an animated planet under a regional mesh.

Runtime

What happens every animation frame (naked)

// main.animate → geocentricScene.render(delta)
if free (or bodies hidden):  surfaceGroup.rotation.y += spin
else if sync + playing:       rotation.y set from dayAccumulator (in applyDiurnalFrame)
else if rotationLocked:       hold lockedRotation

updateCameraMotion()     // entry / fly-home tweens
controls.update()        // orbit damping
updateGlobeCameraClip()  // near/far vs altitude
renderer.render(scene, camera)

Note: scrubbing the timeline does not re-create the sphere. It updates sun direction, optional bodies, and (when layers on) marker groups. The naked globe’s geometry is built once in EarthScene.init.

Watching it rotate

Questions the naked globe answers

Why does the glow rim not crawl with the continents? Atmosphere is not a child of surfaceGroup. Continents spin; shell stays sun-aligned.
Why is half the planet dark even with a light in the scene? Darkness is mostly the shader night map, not just missing directional light. The terminator is authored in the material from ephemeris sun, then lights reinforce it.
Why can’t I see through the Earth when I lower “opacity”? Because it isn’t alpha — it’s surface lift + grid + atmosphere intensity. Opaque shell is intentional.
Why does spin stop when I pause playback in sync mode? Phase freezes. Free mode is the one that always auto-rotates.
Why do stars not spin with Earth? Stars are on scene, not earthGroup. Correct for an inertial backdrop; camera orbit is what moves them relative to the frame.
Where do “layers” attach when I turn them on? Almost always under surfaceGroup (so they co-rotate with land). Field lines are under axisGroup (tilted with spin pole). Atmosphere stays out. That’s Part 2.
